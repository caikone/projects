# 真伪辨别链与证据标签

目标：把「命中了某条信号」这种内部线索，升级为**可外部验证的真伪结论**。

核心认知：**内部判定 ≠ 外部核验。** 信号命中只是「疑似线索」，不是结论。

---

## 六层链路

| 层 | 名称 | 做什么 | 失败时怎么办 |
|---|---|---|---|
| L1 | 正向扫描 | 对照 `red-flags.md` 信号清单逐项核对，记录命中项 | 未命中且语义异常 → 转 L3 广谱核验，不判安全 |
| L2 | 反向证伪 | 非骗局假设检验：能否给出合理的正常解释 | 存在正常解释且无风险动作要求 → 低风险 |
| L3 | 外部证据核验 | 检索公开预警、官方公告、企业/域名/应用信息，核验主体真伪 | 工具不可用 → 标 `[核验未达]`，**不得因此降级风险提醒** |
| L4 | 交叉印证 | 至少 2 个独立来源一致方可升档 | 来源冲突 → 一律降为 `[待核实]` + 人工复核 |
| L5 | 置信度标定 | 按下方 rubric 标 高 / 中 / 低，并写清依据 | 不可标「高」而不给依据 |
| L6 | 人工复核闸门 | 高危结论只作警示与建议，最终动作由用户本人确认 | 不代用户转账、不代联系对方、不代点击链接 |

### L3 触发条件（命中任一即自动发起核验，不必等用户要求）

- 命中任一**一票否决项**（安全账户 / 索要验证码 / 屏幕共享）
- 涉及**具体主体**（某公司、某平台、某机构、某 App）
- 疑似**擦边球**（合法但高压）
- 用户明确要求「帮我查查真假」
- **L1 完全没有命中任何信号，但语义明显异常**（防新型骗术漏判）

### 核验手段优先级

1. 官方渠道：国家企业信用信息公示系统、工信部域名备案、应用市场官方页面
2. 公开预警检索：公安机关、国家反诈中心、监管机构的通报
3. 通用网页检索：以「骗局核心机制」为关键词（不要只用对方提供的名称）
4. 用户侧核验：引导用户通过官方 App / 官方号码自行确认

## 证据标签（所有结论必须带）

| 标签 | 含义 | 输出要求 |
|---|---|---|
| `[已验证]` | 与信号清单条目或直接可查的官方信息命中 | 直接引用命中的条目/来源 |
| `[推断]` | 基于描述与已知套路模式的合理推导 | 必须写明推导依据，不得伪装成事实 |
| `[待核实]` | 关键信息缺失，或依赖外部验证 | 给出核验渠道，不自行断言 |
| `[核验未达]` | 已尝试核验但工具/来源不可用 | 保留风险等级，说明未达原因 |

**呈现规则**：用户陈述与推理结论必须分开写。先写「你提到 X」，再写「据此判定 Y」。禁止把用户的描述直接当成已核实的事实。

## 置信度标定 rubric

| 等级 | 判定标准 | 输出示例 |
|---|---|---|
| **高** | 命中一票否决项；或多个独立来源一致确认为已知骗局；或存在不可辩驳的常识性硬伤 | 「置信度：高——命中『安全账户』一票否决项，公检法不存在此类账户」 |
| **中** | 命中多条高危信号且无合理正常解释，但未取得外部印证 | 「置信度：中——命中 4 项高危信号，反向证伪未找到合理正常解释」 |
| **低** | 信息不足、来源冲突、或属于未收录类型 | 「置信度：低——关键信息缺失，已标 [待核实]，建议 96110 核实」 |

规则：**置信度低不等于风险低。** 置信度描述的是「判断的可靠程度」，风险等级描述的是「危害程度」，两者独立呈现，不得互相替代，更不得用低置信度去弱化红色警告。

## 强提醒卡格式（命中一票否决项或判定时强制输出）

```
========================================
【红色警报】检测到高风险诈骗特征
========================================
判定：{骗局类型}（置信度：{高/中/低}；证据标签：[已验证]/[推断]/[待核实]）
命中证据：
1. {证据 1 —— 引用具体信号编号与用户原话}
2. {证据 2}
您当前的操作风险：{即将泄露验证码 / 即将转账 / 即将共享屏幕}
正确做法：{立即挂断 / 不转账 / 不告知验证码 / 不共享屏幕 / 不点链接}
求助通道：96110 核实；已转账立即 110 并要求紧急止付
========================================
```

禁止省略任何区块，禁止用「建议你注意一下」之类的软表述替代。

## 合理化借口表（防止自我降级）

| 脑子里的借口 | 现实 |
|---|---|
| 「用户只是问问，不是真要转账」 | 询问本身就是风险暴露，照常定级提醒 |
| 「这个看起来像正常聊天」 | 用信号判定，不靠感觉 |
| 「多说两句可能吓到用户」 | 红色场景吓一跳比被骗好 |
| 「先回答用户问题，提醒放后面」 | 红色提醒必须在本轮回答内一并给出 |
| 「工具用不了，算了吧」 | 标 `[核验未达]`，风险等级不变 |
| 「有公司名称，应该不是诈骗」 | 主体真实性只影响擦边球判定，不影响违法硬指标 |
